How it works

From repo to live site in three steps

No FTP, no SSH, no build servers to babysit. Git is your deploy button.

Connect your repo

Sign in with GitHub and choose the repository you want to ship. Public or private, both work.

Pick a branch

Select the branch to deploy, usually main, and turn on auto deploy. Your site files go in public_html/.

Push and you're live

Click Deploy now, or just git push. Each commit is released automatically and served on your domain.

FAQ

Questions, answered

Do I need to know DevOps to use it?

No. If you can push to GitHub, you can deploy. Connect the repo, pick a branch and click Deploy now. We handle the servers.

Where should my site files go in the repo?

Put your public files (like index.html, CSS, JS and images) in a public_html/ folder at the root of your repo. That folder is what visitors see.

Does it work with private repositories?

Yes. Once you connect your GitHub account, you can deploy both public and private repositories.

What happens when I push a new commit?

With auto deploy turned on, each push to your branch fetches that commit, releases it and serves it on your domain automatically.

Can I run Node.js or Python apps?

Yes. Use worker processes to run persistent app instances and background jobs. They restart automatically each time you deploy.

Can I use my own domain?

Absolutely. Point your domain to Verpex and your app is served on it, with a free SSL certificate.
